# Station App rc2 (the radio) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Give every radio a live VFO page in the station app: real readback, capability-driven controls and meters, tuning intents, the owner lock, STOP and the tune carrier, as v0.5.0-rc2.

**Architecture:** `dxberryd` watches the radio records, keeps one rigctld connection per radio (extended protocol, one command at a time), discovers each radio's capabilities once per model, polls at a rate that follows who is watching, and publishes per-radio deltas on the existing events socket. Intents go through an owner lock and guards before they reach the radio. The VFO page is plain JS rendering the radio's state and sending intents.

**Tech Stack:** Go standard library plus the rc1 modules; Hamlib `rigctld` (the Pi's `rigctld@<radio>` units; Debian's `libhamlib-utils` in the test container for the dummy rig); plain HTML/CSS/JS.

**Spec:** `docs/design/2026-10-25-station-app.md` §7 (rig layer), §9.1–§9.2 (sessions, owner lock), §9.4 (the rig-link guard and tune cap only; SWR and PTT are rc3), §10 (status and events), §14 (the VFO page and the Radios additions). rc1's plan (`docs/plans/2026-10-25-station-rc1.md`) is the base.

## Global Constraints

Everything in rc1's Global Constraints, plus:
- Radio names come only from the records file (`/var/lib/dxberry/radios.json`, key `.radios.<name>`, fields used: `label`, `rigctld_port`, `owner`, `ptt.method`, `rig.model`, `rig.control`, `cat`); a name not in the records is 404 everywhere.
- rigctld is spoken only in the extended response protocol (`+\command args`): every reply ends with `RPRT n`; a reply the parser cannot read resets that radio's connection and is logged.
- One command in flight per radio; writes serialize behind reads; 2 s deadline per command (§7.1).
- Poll rates (§7.3): 250 ms while any events socket watches that radio's VFO page, 2 s while any socket is open at all, 10 s with none; meters only while a VFO page is watched; SWR/ALC only while PTT reads on, at 200 ms, one zero frame when it drops.
- Controls and meters the radio does not report are hidden, and the page lists them under "Why isn't X here?" (§7.2). Never a dead control.
- The transmitter has one owner per radio (§9.2): a program session (the record's `owner` is non-empty and its unit is active) or one browser tab. Tuning, mode, VFO, levels and reading are open to every logged-in tab.
- Every intent answers `{ok:true}` or `{ok:false, reason, fix}` with the same words logged (§1 honest UI).
- `provision/VERSION` stays `0.5.0`; the tag is `v0.5.0-rc2`.

## Review Focus

1. A rigctld that answers slowly or garbles a reply must not wedge the radio's queue or crash the poller: Task 2 `TestClientDeadlineResetsConnection`, `TestClientMalformedReplyReconnects`.
2. A radio with no CAT (dummy model 1) must get a page that says "no rig control on this radio" with no dial and no dead controls: Task 3 `TestCapsDummyRigHidesEverythingButPTT`, Task 6 page test `test_vfo_no_cat_layout`.
3. A spot write while a program polls the same rigctld must not corrupt the app's view: the optimistic value is replaced by the next read (Task 4 `TestPollerCorrectsOptimisticValue`).
4. A browser whose events socket drops while it holds the owner claim must lose the claim and any tune carrier within the timeouts: Task 5 `TestOwnerReleasedOnSocketClose`, `TestTuneCarrierCappedAt10s`.
5. A frequency outside the radio's range, a mode not in its caps, a level out of range: refused with reason and fix, never sent (Task 5 `TestIntentRefusesOutOfRange*`).

### Task 2: The rigctld client

**Files:** Create `station/internal/rig/client.go`, `client_test.go`, `testdata/transcript-dummy.txt`.

**Interfaces:**
- Produces: `rig.Dial(addr string, log *slog.Logger) *Client` (reconnect with backoff 1 s doubling to 30 s; `Client.Connected() bool`; `Client.OnState(func(connected bool))`); `Client.Do(ctx, cmd string, args ...string) (Reply, error)` where `Reply{Lines []string; RPRT int}`; one command at a time, queued, 2 s deadline (`ErrDeadline`); `RPRT != 0` returns `*RigError{Code int}`; a malformed reply (no `RPRT` within the deadline, or an echo mismatch) returns `ErrProtocol` and resets the connection.
- Protocol: send `+\<cmd> <args>\n`; read lines until one matching `^RPRT -?\d+$`; the first line echoes `<cmd>: <args>`; value lines are `Name: value`.

**Interfaces:**
- Produces: `type Caps struct { ModelName string; Modes []string; VFOs []string; CanSetSplit, CanGetSplit, CanSetPTT, CanGetPTT bool; SettableLevels, ReadableMeters []string; Hidden []HiddenControl; FreqRanges []FreqRange; Probed time.Time }` where `HiddenControl{Name, Why string}` and `FreqRange{Lo, Hi int64}` from the RX range lines; `rig.Discover(ctx, c *Client) (Caps, error)`: parse `dump_caps`, then probe `get_level` for each of `STRENGTH SWR ALC RFPOWER RFPOWER_METER_WATTS AF RF SQL` (readable = RPRT 0 and a numeric value); settable = listed under "Set level:" in the caps; `rig.CapsCache{Dir string}` with `Load(model string) (Caps, bool)` (one-week age) and `Store(model, caps)`; `Caps.Allows(mode string) bool`, `Caps.InRange(hz int64) bool`.
- Hidden reasons (exact strings): `"this radio does not report %s over CAT"` for a meter, `"this radio cannot set %s over CAT"` for a control, `"rig control is Hamlib's dummy model: this radio has no CAT"` when ModelName is `Dummy`.

### Task 4: The poller and the rig state model

**Files:** Create `station/internal/rig/poller.go`, `poller_test.go`. Modify `station/internal/status/status.go` (per-radio `rig` deltas; `watch` messages from clients).

**Interfaces:**
- Produces: `type State struct { Connected bool; Freq int64; Mode, Passband string; PTT bool; VFO string; Split bool; Levels map[string]float64; Meters map[string]float64; Caps *Caps; UpdatedAt time.Time; Optimistic map[string]bool }`; `rig.NewPoller(c *Client, caps Caps, clock Clock, log) *Poller`; `Poller.Run(ctx)`; `Poller.SetInterest(level Interest)` with `Interest` ∈ {`None` (10 s), `Dashboard` (2 s), `Page` (250 ms + meters)}; `Poller.State() State`; `Poller.Subscribe() <-chan State`; `Poller.Write(ctx, fn func(*Client) error, optimistic func(*State))` applies the optimistic change, runs the write serialized ahead of reads, and lets the next read confirm or correct.
- Events: the client sends `{"type":"watch","radio":"<name>","level":"page"|"dashboard"|"none"}`; the server derives each radio's Interest as the max over all sockets; `{"type":"rig","radio":"<name>","data":<State>}` goes out on every change (coalesced to at most one per poll period).

### Task 5: Owner lock, intents and the radio API

**Files:** Create `station/internal/session/owner.go`, `owner_test.go`, `station/internal/rig/intents.go`, `intents_test.go`, `station/internal/httpapi/radio.go`, `radio_test.go`.

**Interfaces:**
- Owner lock: `session.NewOwners(clock) *Owners`; `Owners.Claim(radio, holder Holder) error` where `Holder{Kind: "tab"|"program"; ID, Label string}`; `Owners.TakeOver(radio, holder) error` (refused with `ErrTransmitting` while the radio's PTT reads on); `Owners.Release(radio, id)`; `Owners.Holder(radio) (Holder, bool)`; a tab's claim is released when its events socket closes, after 10 min without a transmit intent, or by Release. A program holder is derived, not claimed: when `Radio.Owner != ""` and `dxberry-screen@<owner>-<radio>` is active (checked through `cli` every poll of the records), the holder is `{Kind:"program", ID: owner, Label: <program label from dxberry-app list>}` and tabs cannot claim.
- Intents (`rig.Intents{Caps, Poller, Owners}`): `Freq(hz)`, `Mode(mode, passband)`, `VFO(which)`, `Split(on)`, `Level(name, value)`, `Tune(on bool)` (owner only; carrier through `set_ptt 1` in the current mode, auto-off after 10 s; refused in modes `PKTUSB PKTLSB PKTFM RTTY RTTYR` with reason "a data mode would key the sound card with silence; switch to USB or CW to tune"), `ATU()` (owner only; `set_func TUNER 1` only when the caps list TUNER as a settable function and the model is not Dummy; otherwise hidden), `Stop()` (any tab: `set_ptt 0` and end any carrier), `Claim(tab)`, `Release(tab)`, `TakeOver(tab)`. Every intent is refused while `!Connected` with reason `"rig control unreachable; the radio's rigctld is restarting"`, fix `"wait a few seconds"`. Out-of-range or unknown values: reason `"<value> is outside this radio's range"` / `"this radio has no mode <m>"` / `"<level> is not a level this radio sets"`, fix naming the valid range or list.
- Routes: `POST /api/radio/{name}/{freq|mode|vfo|split|level|tune|atu|stop|claim|release|takeover}` with JSON bodies `{hz}`, `{mode, passband?}`, `{vfo}`, `{on}`, `{name, value}`, `{on}`, `{}`, `{}`, `{device}`, `{}`, `{device}`; `GET /api/radio/{name}` → `{radio, state, caps, owner}`. 404 for unknown radio.
