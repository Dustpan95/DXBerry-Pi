# Station App rc3 (audio and PTT) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Two-way audio between the browser and each radio over the LAN with hold-to-talk PTT, the PTT and SWR guards, and two radios worked at once, as v0.5.0-rc3.

**Architecture:** The per-radio PulseAudio moves from the program session to a `dxberry-audio@<radio>` unit the station owns (yielding to programs that open the card directly). `dxberryd` captures the radio's source with `parec`, plays browser audio into a `.tx` null sink with `pacat`, loop-backs that sink to the card only while PTT is held, encodes and decodes Opus through libopus, and carries one WebRTC audio connection per browser per radio with Pion, host candidates only. PTT is a press-and-hold intent with a heartbeat; the SWR guard and the PTT timeouts run in the station.

**Tech Stack:** Go plus `github.com/pion/webrtc/v4`, `github.com/hraban/opus` (cgo, libopus), PulseAudio's `parec`/`pacat`/`pactl` (already on the image for the program sessions), plain JS with the browser's WebRTC and `getUserMedia`.

**Spec:** `docs/design/2026-10-25-station-app.md` §8 (audio), §9.3 (PTT), §9.4 (guards), §14 (PTT, speaker and mic on the VFO page), §15 (the audio unit), §16 risks. rc1 and rc2 plans are the base.

## Global Constraints

Everything in rc1's and rc2's Global Constraints, plus:
- Audio objects per radio are named exactly as the program modules expect: sink `<CARD>`, source `<CARD>.in`, plus the new null sink `<CARD>.tx`; `CARD` is the radio name upper-cased (`dxb_apps_wiring`'s `card`).
- The sound server runs as `dxbapps` on `/run/dxberry/audio/<radio>/native`; program sessions connect through `PULSE_SERVER`; the server is stopped for the duration of an ALSA program's session (WSJT-X, flrig, Pat: `app_<a>_audio` is `alsa`) and the page says "<Program> has the sound card; no browser audio while it runs" (§8.1).
- Opus 48 kHz mono 20 ms, RX 32 kbit/s, TX 24 kbit/s, in-band FEC on (§8.2). WebRTC: audio only, host candidates only, UDP 50000–50199, no STUN/TURN (§8.3). The microphone is requested only on the first PTT press (§8.3).
- PTT is press-and-hold with a 5 s heartbeat; the station drops PTT when the heartbeat stops for 7 s, at the per-radio timeout (default 180 s, range 30–600 s from rc2's settings), on the owner socket closing, on an SWR trip, or on STOP from any tab (§9.3).
- The mic track is enabled and the TX loopback loaded only while PTT is on (§8.1, §9.3). `vox`/`none` PTT methods key nothing; `digirig_tone` adds the plumbing spec's tone on the `.tx` sink during the PTT window.
- SWR guard only on radios whose caps list SWR as readable: three consecutive 200 ms reads over the limit → PTT off, carrier off, latch; cleared by band change, a successful ATU tune with the next read under the limit, or a confirmed override (§9.4). STOP and the guard unkey the radio whoever keyed it (§9.4).
- Never the PC microphone or any device other than the radio's: a missing sound server or `.tx` sink refuses PTT with the device name in the reason (§9.4).
- `provision/VERSION` stays `0.5.0`; the tag is `v0.5.0-rc3`; after the owner's checks the full `v0.5.0` tag follows under the standing go.

## Review Focus

1. PTT must never stay on: heartbeat loss, socket close, timeout, SWR trip, STOP, and `dxberryd` itself exiting (a shutdown hook sends `set_ptt 0` and unloads the loopback) are each tested (Task 4 `TestPTTDropsOn*`, Task 4 `TestShutdownUnkeys`).
2. A browser that reconnects mid-PTT must not truncate or re-key: the new socket adopts the state silently and the old claim's PTT is dropped by the heartbeat rule, never by a stale "ptt off" from the other tab (Task 4 `TestStalePTTOffIgnored`).
3. The SWR guard must never trip from a single bad read or from the ATU's own carrier (Task 5 `TestSWRGuardNeedsThreeFrames`, `TestSWRGuardSuppressedAroundATU`).
4. An ALSA program's session starting while a browser listens must stop the audio cleanly with the right notice and restart the server after (Task 1 `test_audio_unit_yields_to_alsa_program`, Task 6 `TestAudioStoppedNoticeOnProgramStart`).
5. Two radios: two sound servers, two WebRTC connections, two owners, no cross-talk between card names (Task 2 `TestTwoRadiosIsolatedSinks`, Task 3 `TestTwoPeerConnectionsSeparateTracks`).

### Task 2: Server control, capture and playback pipes

**Files:** Create `station/internal/audio/server.go`, `server_test.go`, `capture.go`, `capture_test.go`.

**Interfaces:**
- `audio.NewServerControl(cli *cli.CLI, runDir string) *ServerControl`; `Ensure(ctx, radio) error` (start the unit through `systemctl start dxberry-audio@<radio>`; wait for the socket up to 5 s); `Available(radio) (bool, reason string)` (socket present and `pactl --server unix:… list short sinks` lists `<CARD>` and `<CARD>.tx`; reasons: `"no sound server for <radio>: <Program> has the sound card"` when the record's owner is an alsa program, `"no sound server for <radio>: /run/dxberry/audio/<radio>/native is missing"` otherwise); `LoadTXLoopback(ctx, radio) (moduleID int, err)` = `pactl load-module module-loopback source=<CARD>.tx.monitor sink=<CARD> latency_msec=20`; `UnloadTXLoopback(ctx, radio, moduleID)`.
- `audio.NewCapture(server string, source string) *Capture` runs `parec --server=<socket> --device=<CARD>.in --format=s16le --rate=48000 --channels=1 --latency-msec=20` and yields `[]int16` frames of 960 samples (20 ms) on `Frames() <-chan []int16`; restarts the process once on exit, then reports `Err()`. `audio.NewPlayback(server, sink)` runs `pacat --playback --server=… --device=<CARD>.tx --format=s16le --rate=48000 --channels=1 --latency-msec=20` and accepts `Write(frame []int16) error`.
- Tests use fake `parec`/`pacat`/`pactl` scripts on PATH (`DXB_AUDIO_BIN` override) that stream a known PCM pattern / record what they received.

### Task 3: Opus and WebRTC

**Files:** Create `station/internal/audio/opus.go`, `opus_test.go`, `webrtc.go`, `webrtc_test.go`, `station/internal/httpapi/audio.go`, `station/web/audio.js`. Modify `station/go.mod` (pion/webrtc/v4, hraban/opus) via the `gotidy` container; the test image needs `libopus-dev` and `libopusfile-dev` (Dockerfile; rebuild).

**Interfaces:**
- `audio.NewEncoder() (*Encoder, error)` 48 kHz mono, bitrate set per call site, FEC on; `Encode([]int16) ([]byte, error)`; `audio.NewDecoder()`; `Decode([]byte) ([]int16, error)` with PLC on loss (`DecodeLost()`).
- `audio.NewBridge(radio string, cap *Capture, play *Playback, ports PortRange, log) *Bridge`; `Bridge.Connect(ctx, offerSDP string, tab TabID) (answerSDP string, err)` builds a Pion `PeerConnection` with a `SettingEngine` that sets the UDP range 50000–50199 and no ICE servers, one outbound Opus track fed by the shared encoder (one encoder per radio for every listener), one inbound track whose packets are decoded and written to `Playback` only while `Bridge.TXAllowed(tab)` is true (set by the PTT layer); `Bridge.Close(tab)`; `Bridge.Listeners() int`; a connection with no inbound RTP (or no outbound ack) for 5 s is closed and the client told `{"type":"audio-lost"}`.
- `WS /api/audio/{radio}/signal`: JSON `{"type":"offer","sdp":…}` → `{"type":"answer","sdp":…}`; `{"type":"ice",…}` trickle both ways; `{"type":"close"}`. Requires session and same-origin; refuses with `Available`'s reason when the radio has no sound server.
- `audio.js`: `dxbAudio.listen(radio)` (creates the peer connection, plays the remote track in an `<audio>` element after a user gesture), `dxbAudio.openMic()` (first PTT press only; `getUserMedia({audio:{echoCancellation:false, noiseSuppression:false, autoGainControl:false}})`), `dxbAudio.setTX(on)` (enables the mic track and ducks RX by 20 dB), `dxbAudio.stop()`; reconnect on `audio-lost` with a visible "audio lost, tap to reconnect" chip.

### Task 4: PTT

**Files:** Create `station/internal/rig/ptt.go`, `ptt_test.go`. Modify `station/internal/httpapi/radio.go` (`POST /api/radio/{name}/ptt {on, hb?}`), `station/internal/rig/intents.go` (PTT uses the owner lock), `station/web/vfo.js` (PTT button, heartbeat, release on pointer cancel/blur/pagehide), `station/cmd/dxberryd/main.go` (shutdown hook).

**Interfaces:**
- `rig.NewPTT(intents *Intents, bridge *audio.Bridge, server *audio.ServerControl, settings func() RadioSettings, method string, clock, log) *PTT`; `PTT.On(tab) error` (owner only; `Available` must be true when audio TX is requested; loads the TX loopback; `set_ptt 1` for methods `rigctld|cm108|gpio`, nothing for `vox|none`, the keying tone for `digirig_tone`; `bridge.TXAllowed(tab)=true`; starts the timeout and heartbeat timers); `PTT.Heartbeat(tab)`; `PTT.Off(tab, reason)` (idempotent; `set_ptt 0` retried every 1 s while the rig link is down until confirmed; unloads the loopback; `TXAllowed=false`; a notice `{"type":"ptt","radio","on":false,"reason"}` to every tab); automatic Off reasons: `"heartbeat lost"` (7 s), `"PTT timed out at M:SS"`, `"owner disconnected"`, `"SWR guard"`, `"STOP from <device>"`; `PTT.Shutdown()` called from main on SIGTERM.
- Stale-release rule: an `Off` from a tab that is not the current owner is ignored (reply `{ok:false, reason:"you do not hold the transmitter"}`), so a reconnecting old tab cannot unkey the new owner; the heartbeat rule handles the old owner's dropout.

### Task 5: The SWR guard

Modify `poller.go` (feeds SWR reads while PTT is on), `intents.go` (every transmit intent consults the latch; band change and successful ATU clear it; `Override(tab)` route `POST /api/radio/{name}/override`), `vfo.js` (banner with Run ATU and Override behind an in-page confirmation "Transmit anyway into a bad match? **Interfaces:**
- `rig.NewSWRGuard(limit func() float64, clock) *SWRGuard`; `Observe(swr float64, pttOn bool)` → returns `Tripped` on the third consecutive over-limit read while PTT on; `Latched() bool`; `Reason() string` = `"SWR guard: %.1f:1 against %.1f:1; tune the antenna, change band, or override"`; `ClearForBandChange()`, `ClearAfterATU(nextSWR float64) bool`, `Override()`; `SuppressAroundATU(d time.Duration)` (30 s window during which reads are ignored). - On trip: `PTT.Off(owner, "SWR guard")`, carrier off, `set_ptt 0` regardless of who keyed, log line `radio <name>: SWR guard tripped %.1f:1 (limit %.1f)`, notice `{"type":"guard","radio","latched":true,"reason"}`; on clear a notice with the clearing cause.
