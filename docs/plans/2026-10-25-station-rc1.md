# Station App rc1 (parity) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Replace Cockpit with DXBerry's own station app (`dxberryd`) so the Pi does everything 0.4.0-rc1 does, from the new app, as v0.5.0-rc1.

**Architecture:** One Go service behind nginx on 443 serves an embedded plain-JS frontend, authenticates with PAM, and runs the existing `dxberry-*` CLIs through an allowlisted API. The 0.4.0 page code is ported nearly intact over a small compatibility layer (`dxb.run` in place of `cockpit.spawn`, an app WebSocket in place of Cockpit's channel for noVNC). Provisioning installs the binary and removes Cockpit; CI builds the binary on an arm64 runner and the release carries it in the tarball and the image.

**Tech Stack:** Go (Debian trixie's toolchain, no version pin), `github.com/msteinert/pam` (cgo), `github.com/coder/websocket`, `github.com/creack/pty`, plain HTML/CSS/JS, vendored noVNC (existing) and xterm.js, bash 5 + awk + jq for provisioning, nginx.

**Spec:** `docs/design/2026-10-25-station-app.md` (sections cited as §N). This plan covers §19's rc1; rc2 (rig layer, VFO) and rc3 (audio, PTT, guards) are separate plans.

## Global Constraints

- No attribution lines of any kind in files, commits or tags (CI guard: `git grep -qIiE 'co-?auth[o]red-?by|cla[u]de|anthr[o]pic'`). Commit as `git -c user.name="Dustpan95" -c user.email="Dustpan95@users.noreply.github.com"`.
- GPLv2. Nothing copied from any other project; noVNC and xterm.js are vendored unmodified with their licenses.
- No version pins: Debian packages and Go toolchain unpinned; Go module versions are whatever `go get` resolves and `go.sum` records (that is a lockfile, not a pin; never hand-edit it to an older version).
- Tests and shellcheck run ONLY in the container `/home/dustin/docker/dxberry-tests/` (`sudo docker compose -f /home/dustin/docker/dxberry-tests/compose.yml run --rm tests bash -c '<cmd>'`), never on the docker host. The container has no network: Go modules come from a module cache baked into the image (Task 1).
- Every API request is same-origin only (§5.4): session cookie plus `Sec-Fetch-Site: same-origin` or a matching `Origin`, else 403. WebSockets check `Origin` the same way.
- No client-supplied path ever reaches the filesystem; no generic command endpoint (§5.5). Names match `^[a-z][a-z0-9-]{0,31}$`; session names `^[a-z][a-z0-9]*-[a-z][a-z0-9-]*$` (app-radio) as `dxberry-app` validates them.
- Secrets travel on stdin to the CLIs, never in arguments or logs (§5.5). Passwords are never logged.
- Root is refused at login; a user must be in group `sudo` (§6.1).
- `dxberryd` listens on `127.0.0.1:8090` only in this release (§5.1); nginx owns 443 and 80.
- Frontend: plain HTML/CSS/JS, no build step, no framework, no external resources, no `innerHTML` (the 0.4.0 page rule), served embedded in the binary (§14).
- Parity bar is the 0.4.0-rc1 page as shipped (§19): every flow, every refusal text, the settings confirm/revert, network settings gated off, update roll-back, kept-settings notices, the logbook dialog with stdin-only key entry.
- `provision/VERSION` becomes `0.5.0`; the tag is `v0.5.0-rc1`.
- bash discipline as in the earlier specs: `dxb_` prefixes, idempotent steps, write-if-changed, one daemon-reload, `--json` with fixed exit codes.

## Review Focus

1. A request without the session cookie, or with a cookie but a foreign `Origin`, to any `/api/` path or WebSocket must get 401/403 and never run a command (Task 2 tests `TestAPIRefusesWithoutSession`, `TestAPIRefusesForeignOrigin`, Task 6 `TestVNCRefusesForeignOrigin`).
2. A `/api/cli/` call with an argument outside the allowlist (a path, a shell metacharacter, an unknown unit) must be refused before exec with the reason (Task 3 `TestCLIRefusesUnknownCommand`, `TestCLIRefusesBadArgument`, `TestCLIRefusesUnknownUnit`).
3. A `dietpi` password with spaces or non-ASCII must work and never appear in the journal (Task 2 `TestLoginPasswordNeverLogged`).
4. The update from 0.4.0-rc1 on a Pi with Cockpit running must end with Cockpit gone, 443 answered by nginx, Pat and Wavelog still gated, and a second provisioning run changing nothing (Task 9 bash tests `test_station_removes_cockpit`, `test_station_idempotent`; hardware check Task 12).
5. A program window or terminal WebSocket must close when the session cookie is invalid or the unit is not active, never relaying bytes (Task 6 `TestVNCRefusesInactiveSession`, Task 7 `TestTermClosesOnLogout`).
